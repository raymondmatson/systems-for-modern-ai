# Visual Design Phase 8 — Initial-five coverage audit and calibration

**Status:** implementation/audit complete; fresh pinned post-change regression/accessibility rerun still required before Phase 8 closes.  
**Date:** 2026-09-11

## Scope

Phase 8 audits the already-generic visual renderer across every currently enterable context in the five initial systems. It does not add product semantics. Geometry, routing, compaction, and media/label fitting remain discardable presentation state.

The exhaustive audit is generated by `scripts/validation/phase8_visual_coverage.py`, using the same enterability rule as `scripts/content/audit_physical_orientation.py`. The script materializes the exact current Explore view-model and `src/app/explore` component tree through the dependency-light renderer adapter, then performs source-geometry and system-Chromium checks.

## Corrections justified by the audit

The audit found presentation-only failures that were bounded and corrected:

1. **Blocked binary routing.** Some two-endpoint paths could take an orthogonal corridor through an unrelated sibling card. Binary routing now escapes the endpoint shell into a row/column gap before taking an outside corridor when simple elbows are blocked.
2. **Multi-row n-ary routing.** N-ary relationships spanning multiple rows now use a side bus plus row buses outside the visible node envelope rather than a trunk that can cut through unrelated cards.
3. **Boundary routing.** Visible-child boundary continuations choose deterministic clear detours around sibling cards. When the modeled endpoint is the current enclosure itself and no visible child endpoint exists, the stub remains in the enclosure gutter instead of extending inward through a child.
4. **Terminal Anatomy-only density.** A terminal context with Anatomy but no semantic children no longer reserves an empty semantic field above the Anatomy support region. This does not assert physical placement or dimensions.
5. **Name-fit threshold.** Exactly 30-character component names enter compact no-image fallback before truncation, preserving the media-capable shell contract while prioritizing readable labels.
6. **Sparse layout minima.** Generic/system/rack derived minimums are tightened where content does not require the former height. No U positions, measured dimensions, or physical distances are inferred.

## Regression boundaries

The corrections do not alter canonical containment, Cross-Connection identity/type/directionality, Context Locators, Expansion Mode, Selection, Scenario targeting, Anatomy interactivity, or the presentation-only Ironwood torus contract.

The Phase-7 Ironwood/Cerebras transfer validator passes after these changes, and the current-renderer benchmark remains within the established SVG-first/no-virtualization envelope. Unit contracts were extended for Anatomy-only compaction, blocked binary detours, multi-row n-ary buses, visible-child boundary collision avoidance, and gutter-only enclosure-level stubs.

## Playwright locator regression lesson

Phase-7 Ironwood E2E work reintroduced a previously fixed locator ambiguity by using a loose short action name. Playwright accessible-name role matching is case-insensitive substring matching unless exact matching is requested; `getByRole('button', {name: 'Enter'})` therefore also matched labels containing `Data-center`.

Future tests must use the shared `enterAction(page)` helper or `getByRole('button', {name: 'Enter', exact: true})` for the Enter action. Apply the same discipline to other short generic actions when entity or relationship names could contain the action text. This is a test-locator rule, not an application/topology semantic change.
